## Amazon EC2

AWS 對 EC2（Elastic Compute Cloud）的描述是「**安全、可調整大小的雲端運算容量**」。簡單說，就是**在雲端租一台虛擬伺服器**。你可以在上面安裝任何作業系統和軟體，用來架網站、執行應用程式或資料庫。

和傳統做法比較，就能看出 EC2 的價值。自建機房要先採購硬體、等貨送到、上架、安裝設定，往往要花好幾週；EC2 **幾分鐘就能開好一台**，不用時就關掉，只為用到的時間付費（呼應雲端「變動支出取代固定支出」「提升速度與敏捷」）。

**使用 EC2 的三個步驟：**

```
1. 啟動（Launch）：選一個 AMI（系統範本）＋ 選 instance type（硬體規格）
2. 連線（Connect）：用 SSH（Linux）或 RDP（Windows）連進去
3. 使用（Use）：裝軟體、跑你的應用
```

>  同一台實體主機上，AWS 用虛擬化切出多台 EC2 給不同客戶，彼此隔離互不干擾。這種做法叫「多租戶」：你用起來像獨占一台機器，實際上是和別人共用底層硬體。

## EC2 執行個體類型

不同工作需要的硬體不一樣：有的需要很強的 CPU，有的需要大量記憶體。AWS 依照每種機器加強的硬體，主要分成**五大類**，讓你依工作的瓶頸挑選。
| 類型 | 最佳化方向 | 適合場景 |
|------|---------|---------|
| **General Purpose（通用型）** | 運算 / 記憶體 / 網路**均衡** | 網站、應用伺服器、中小型資料庫；不確定選哪一類時的預設選擇 |
| **Compute Optimized（運算最佳化）** | 高 CPU | 高效能運算（HPC）、批次處理、遊戲伺服器、ML 推論 |
| **Memory Optimized（記憶體最佳化）** | 大記憶體 | 大型記憶體內資料庫、即時處理大量資料 |
| **Storage Optimized（儲存最佳化）** | 高速本地儲存、高 IOPS | 資料倉儲、分散式檔案系統、需要大量本地讀寫的工作 |
| **Accelerated Computing（加速運算）** | GPU / 專用晶片 | 機器學習訓練、繪圖渲染、大量浮點運算 |

> - 題目提到「需要大量記憶體跑記憶體內資料庫」：選 **Memory Optimized**
> - 題目提到「機器學習訓練」或「GPU」：選 **Accelerated Computing**
> - 題目提到「不確定」或「一般網站」：選 **General Purpose**
> - 每個類別底下還分成很多**家族（family）與世代**，例如 m7i、c7g。型號不必背，只要認得**開頭的字母屬於哪一類**就好。

[ec2instances.info](https://instances.vantage.sh/) 是第三方的開源工具，把所有機型的規格和價格整理成一張表。規格包括 vCPU、記憶體和本機硬碟；價格則列出 Linux 和 Windows 在隨需、預留兩種計費方式下的每小時費用。這張表可以搜尋、排序和篩選，實務上常用來挑選機型、比較成本。

## 開機前要懂的三個東西

- **AMI（Amazon Machine Image，系統映像）**：預先打包好的範本，內含**作業系統和預裝軟體**。選哪一個 AMI，就決定了這台機器開機後的樣子，例如 Amazon Linux、Windows Server，或已經裝好 WordPress 的映像。
- **Key Pair（金鑰對）**：用 SSH 登入時的「**鑰匙**」。AWS 會給你一個私鑰檔，連線時用它證明你的身分。**私鑰一定要保存好，弄丟了就無法再下載。**
- **Security Group（安全群組）**：這台 EC2 的**防火牆**。新建的安全群組預設擋掉所有連入流量，你要手動開放需要的 port（SSH 22、HTTP 80）。

## 執行個體狀態與生命週期

EC2 開好之後，能做的事不只有「開機」和「刪除」。下面這幾個動作的差別，直接關係到會不會繼續被收費：

| 動作 | 發生什麼 | 還在收費嗎 |
|------|---------|-----------|
| **Stop（停止）** | 關機，保留根磁碟與資料，可再開機 | 運算費停收，**但 EBS 磁碟仍收費** |
| **Reboot（重開機）** | 重新開機，資料與設定不變 | 照常 |
| **Hibernate（休眠）** | 把記憶體內容存到 EBS，下次開機回到原狀態 | EBS 仍收費 |
| **Terminate（終止）** | 刪除執行個體，預設一併刪掉根 EBS | 運算停收，**但殘留資源可能還在收費** |

- **Stop 不代表不收費**。這就像引擎熄火了，車卻還停在收費停車場：EBS 磁碟會繼續計費。確定不用了，就要 **Terminate**。但 Terminate 也**不一定會刪乾淨**：額外掛載的 EBS、快照、Elastic IP、負載平衡器都可能留下來，繼續收費。練習完務必回頭檢查並刪除。
- **EC2 需要儲存空間**：每台 EC2 都有一顆**根磁碟（通常是 EBS）**，你的資料就存在上面。

## 與 AWS 互動的方式

> **你在 AWS 上做的每一件事，本質上都是一次 API 呼叫。**

各種操作方式的差別，只在於你用什麼工具發出這個呼叫：

| 方式 | 是什麼 | 適合 |
|------|--------|------|
| **管理主控台（Management Console）** | 網頁圖形介面，點選操作 | 初學、手動操作、視覺化探索 |
| **CLI（命令列介面）** | 用指令操作，可寫成腳本 | 自動化、重複性操作 |
| **SDK** | 在你的程式碼裡呼叫 AWS（Python、Java…）| 應用程式直接整合 AWS |
| **CloudFormation** | **基礎設施即程式碼（IaC）**：用範本宣告要哪些資源 | 可重複、一致地部署整套環境 |
| **Elastic Beanstalk** | 你提供程式碼與設定，它自動幫你建立 EC2 / ELB / Auto Scaling | 不想自己一項項設定基礎設施 |

> - 題目提到「用網頁介面點選操作」：選 **Console**
> - 題目提到「寫成腳本自動化」：選 **CLI**
> - 題目提到「用範本重複部署」或「基礎設施即程式碼」：選 **CloudFormation**

## EC2 計費

同一台機器有五種付費方式，差別在「有沒有事先承諾」與「能不能被收回」：

| 計費方式 | 怎麼算 | 折扣 | 適合 |
|---------|--------|------|------|
| **On-Demand（隨需）** | 用多少付多少，**無承諾** | 無 | 短期、不可預測、開發測試 |
| **Savings Plans（節省方案）** | 承諾 **1 或 3 年**內每小時花固定金額（以 $/小時計）| 最高約 **72%** | 用量穩定、想省錢又保留彈性 |
| **Reserved Instances（預留執行個體）** | 承諾 **1 或 3 年**特定規格 | 最高約 **72%** | 長期穩定、可預測的負載 |
| **Spot Instances（競價執行個體）** | 用 AWS 的**閒置容量** | 最高約 **90%** | **可中斷**的工作：批次、無狀態、容錯 |
| **Dedicated Hosts（專屬主機）** | 整台**實體主機**專屬給你，可看到主機 ID、sockets / cores | — | **BYOL**（自帶授權）或法規要求掌握實體硬體資訊 |

- **Spot 最便宜，但 AWS 需要容量時會收回**，收回前大約只有 **2 分鐘**的警告。所以 Spot **只適合可以被中斷、之後能重跑的工作**，絕對不要把「不能中斷的關鍵服務」放在 Spot 上。
- **Savings Plans vs Reserved**：兩者都是用「承諾」換折扣。Savings Plans 承諾的是每小時花費的金額，比較有彈性；Reserved 承諾的是特定規格，限制比較多。其中 Compute Savings Plans 不只適用 EC2，也涵蓋 Fargate 和 Lambda，不過折扣上限較低，最高約 66%。
- **Dedicated Instances vs Dedicated Hosts**：兩者的硬體都不和**其他客戶**共用。不同的是，Dedicated Instances 由 AWS 決定執行個體放在哪台主機，你看不到底層的實體機器。Dedicated Hosts 則把整台實體主機交給你：你能看到 socket 和 core 的數量，也能控制執行個體放在哪台主機。這一點對 **BYOL（Bring Your Own License，自帶授權）** 很重要，因為 Windows Server、SQL Server 等軟體的授權，常依實體 socket 或 core 的數量計費。
- 題目提到「BYOL」或「把現有的軟體授權帶到 AWS」，選 **Dedicated Hosts**。如果只需要「實體隔離，但不在意放在哪台主機」，選比較便宜的 **Dedicated Instances**。

## EC2 Auto Scaling

Auto Scaling 讓 EC2 的數量**依需求自動增減**。傳統機房得照**尖峰**時的需求，準備一堆平常閒置的機器；有了 Auto Scaling，**流量大時自動增加機器，流量小時自動移除**，既省錢，系統也不會因為流量暴增而當機。

**水平擴展和垂直擴展**：Auto Scaling 做的是**水平擴展（scale out）**，也就是增減機器的數量。把單一台機器升級成更強的規格，則叫垂直擴展（scale up），這不是 Auto Scaling 的工作。

| | 垂直（升級單機） | 水平（加減機器） |
|---|---|---|
| 規模上限 | 有天花板 | 近乎無上限 |
| 升級時 | 通常要停機 | 不停機 |
| 故障風險 | 只有一台，壞了整個服務就停擺 | 一台故障，其他台仍能運作 |

**常見的擴展策略：**

| 策略 | 說明 |
|------|------|
| **動態擴展（Dynamic）** | 依**當下**指標（如 CPU 使用率）即時增減 |
| **預測擴展（Predictive）** | 依**歷史模式預測**未來需求，提前準備 |
| **排程擴展（Scheduled）** | 在**預先排定的時間**增減，例如每週一早上加機器 |

設定 Auto Scaling 時，要定義三個數量：**最小（minimum）**、**期望（desired）**、**最大（maximum）**。它們分別決定最少要有幾台、平常維持幾台、最多可以增加到幾台。

## Elastic Load Balancing（ELB）

ELB 是 AWS 代管的負載平衡器（Load Balancer），會把進來的流量**分配到多台 EC2**，而且只送給健康的機器。如果某台 EC2 已經當機，流量卻還是送過去，使用者就會收到錯誤。為了避免這種情況，ELB 會用健康檢查（Health Check）持續確認每台機器的狀態，自動跳過故障的機器，使用者完全不會察覺。這就是高可用（High Availability）。

**為什麼 ELB 常和 Auto Scaling 搭配使用：** Auto Scaling 決定「要有幾台機器」，ELB 決定「流量怎麼分給這些機器」。機器增加時，ELB 會自動把新機器加入分配名單；機器被移除或故障時，ELB 也會自動把它從名單中拿掉。

```mermaid
architecture-beta
    group cloud(cloud)[AWS Cloud]
    group asg(cloud)[Auto Scaling Group] in cloud

    service user(internet)[User Traffic]
    service elb(aws:aws-elastic-load-balancing-application-load-balancer)[ELB] in cloud
    junction j in cloud
    service ec2a(aws:amazon-ec2-instance)[EC2] in asg
    service ec2b(aws:amazon-ec2-instance)[EC2] in asg
    service ec2c(aws:amazon-ec2-instance)[EC2] in asg

    user:R --> L:elb
    elb:R --> L:j
    j:T --> L:ec2a
    j:R --> L:ec2b
    j:B --> L:ec2c

    align row elb j ec2b
    align column ec2a ec2b ec2c
```

*ELB 只把流量分給健康的 EC2。這些 EC2 都屬於同一個 Auto Scaling 群組：流量大時，群組自動增加機器；流量小時，自動移除機器。ELB 也會跟著把新機器加入名單、把移除的機器拿掉。*

## 重點整理

- **EC2** = 雲端上可調整大小的虛擬伺服器；幾分鐘開好、用多少付多少；底層用虛擬化隔離不同客戶（多租戶）
- **執行個體類型**：General Purpose（均衡）、Compute Optimized（高 CPU）、Memory Optimized（大記憶體）、Storage Optimized（高速本地儲存）、Accelerated Computing（GPU）
- **開機三要素**：AMI（系統映像）、Key Pair（SSH 金鑰）、Security Group（防火牆，需自己開放 port）
- **與 AWS 互動的方式**：Console（網頁手動）、CLI（腳本）、SDK（程式碼）、**CloudFormation（IaC、可重複部署）**、Elastic Beanstalk（自動建立環境）
- **計費**：On-Demand（無承諾，最有彈性）、Savings Plans / Reserved（承諾 1 或 3 年換折扣，最高約 72%）、Spot（使用閒置容量，最省約 90%，**可能被收回**）、Dedicated Hosts（專屬實體主機，用於法規或授權需求）
- **水平 vs 垂直擴展**：垂直有上限、要停機、有單點故障；水平近乎無上限、可用性高。雲端偏好水平擴展

| 情境需求 | 答案 |
|---------|------|
| 短期、不可預測、開發測試的負載 | **On-Demand** |
| 長期穩定、可預測、想省錢 | **Savings Plans / Reserved Instances** |
| 可中斷的批次工作、要最省錢 | **Spot Instances** |
| 法規 / 軟體授權要求專屬實體主機 | **Dedicated Hosts** |
| 流量起伏大，要自動增減機器 | **EC2 Auto Scaling** |
| 把流量平均分配到多台健康主機 | **Elastic Load Balancing** |
| 用範本可重複部署整套基礎設施 | **CloudFormation（IaC）** |
| 需要大記憶體跑記憶體內資料庫 | **Memory Optimized** 執行個體 |
